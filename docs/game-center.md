# new-api 游戏中心

游戏中心仍默认关闭，管理员可逐个开放游戏。前端仅在 `web/classic/`。

## 房间和邀请

- 对战游戏声明桌人数，框架支持 2～8 个座位。五子棋、四子棋、黑白棋、中国象棋、石头剪刀布使用双人桌，斗地主使用三人桌。
- 玩家入座时预扣该房间的固定押注，所有座位坐满后自动开局。开局前离座退回押注；房主离开或取消时关闭房间，退回所有成员押注。
- 房间可公开或私密，也可设置密码。密码仅保存哈希；快速匹配跳过私密房及密码房。
- 邀请链接先通过 `GET /api/game/rooms/invite?code=…` 读取游戏、押注、实际预扣额、座位数和锁定情况。预览不会入座或扣币，也不会公开成员或局面。确认加入后才提交 `POST /api/game/rooms/join`。
- 房间成员使用 `members` 返回座位、昵称、净输赢和 `result`（`win/loss/draw`，未结束时为空）。已移除旧的 `players/guest_id/host_net/guest_net` 响应字段。数据库 `players` 列仍保存实际入座人数。
- 本分支从未部署，已删除旧双人房间回填迁移。新库由 GORM 初始化房间及座位表。

## 斗地主

使用 54 张牌，三人各 17 张，另留 3 张底牌。首叫座位随机，依次选择不叫或 1～3 分；非零叫分必须高于已有叫分。叫 3 分直接成为地主，否则三人叫完后最高分者成为地主。全部不叫会重新洗牌，并轮换首叫座位。地主获得底牌并首先出牌。

支持单张、对子、三张、三带一、三带二、顺子、连对、飞机、飞机带单牌或对子、四带二、四带两对、炸弹及王炸。顺子、连对和飞机机身不能包含 2 或王；同类牌型需具有相同长度，按最高点数比较。飞机单翼可用对子作为两张单牌，机身与翅膀不能共用点数；四带二可带一个对子，四带两对需两个不同点数的对子。

玩家只能使用自己的牌。连续两人不出后，由最后出牌者重新领出；领出时不能选择不出。地主先出完则地主获胜；任一农民先出完，则两位农民共同获胜。认输或超时使该玩家所在队伍判负；叫分阶段尚未组队时，其余两人获胜。

叫分和炸弹不改变押注、不追加扣币。输家损失固定押注，赢家平分输家押注，整数余数按座位从小到大分配。多人桌按每位赢家的净赢额抽成，双人桌保持原有奖池抽成，均向下取整。友谊赛也记录团队胜负；分配到零收益的队友仍记为胜。余额越界时整局结算事务回滚，不能部分派彩。

叫分期间底牌隐藏，游戏中只返回玩家自己的手牌及所有人的剩余张数；自然结束后公开剩余手牌。超时或认输以房间外层状态标记结束，不额外公开对手手牌。

## 玩法分区与联机大厅

游戏中心按玩法分区展示，原有结算方式保留为标签和筛选。`/games/lobby` 汇总各对战游戏的公开等待房间，并单列自己的未结束房间。

`GET /api/game/lobby` 返回 `rooms` 和 `active_rooms`，可通过 `game` 查询参数筛选。关闭游戏和私密房间只对参与者提供恢复入口，其他玩家看不到。游戏中心关闭后已有对局仍可继续。大厅加入房间同样先显示押注、实际扣币额、人数及密码输入，成功加入后进入对应游戏。

## 引擎扩展

游戏使用现有 `pvpEngine` 提供状态创建、出牌、视图和超时判定。多人游戏同时实现 `pvpMultiplayer`：

- `Seats()` 返回该游戏要求的桌人数。
- `Winners(state, loserSeat)` 返回获胜座位列表；`loserSeat=-1` 表示自然结束，否则按超时或认输座位判断团队胜负。

框架统一处理密码、匹配、入座、长轮询、版本冲突、固定押注池结算和恢复。JSON 编解码使用 `common` 包；数据操作通过 GORM，并使用项目的数据库锁辅助函数。
