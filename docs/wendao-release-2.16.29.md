# v2.16.29 问道发布记录

日期：2026-11-04。范围为 v2.16.28 之后的 S4–S6 与发布收口，不新增第六境界、寿元、下院争夺或秘境第三重专属敌人，不调整现有发币预算。

## 玩家可见变化

- 历练章节、支线、问心阶与周天试炼使用即时斗法，保留剧情、进度、机缘与奖励；五地域敌人、养成折算与服务端逐帧重放核对同步。
- 世界页增加游历、灵脉打坐和持久分项回流说明；游历整趟最多积累 12 小时，灵脉与宗门自然产出每次离线补算最多 12 小时，互斥活动由同存档事务检查。
- 掌门可在已到达的异地建下院并派弟子驻守；金丹师长可收亲传，记录师承与代数，符合条件的徒弟自然修为增加 15%。
- 斗法暂停/失焦清除旧输入，触屏摇杆保持首指归属，同一按钮多指互不误释放；离开页面取消延迟结局回调。
- 新增可复现游戏表组件工具、完整站点升级工具、奖励经济核对说明与定向回归，并接入 CI。

## 存档与运行边界

当前 `SaveSchema=13`。v2.16.28 的 schema7 旧卡牌历练会结束，退还尚未使用的丹符，已完成节点、培养和资产保留。当前版与认识 schema 的旧版均会拒绝自己不支持的未来格式；不支持把新存档回写到旧程序继续使用。升级前保留完整数据库备份，出现合法存档无法保存、资产重复/丢失或结算不一致时停止新增写入、保留场次和日志，采用理解 schema13 的修复版本向前修复。

发币仍只有九幽秘境与宗门大比进入原有统一规则。**`DailyRewards=0` 停止新增领奖资格，已有待发权益仍可能在累计有效时长补足后发放**；它不是冻结全部支出的开关。恢复配置不会重新计算已经结束场次的币奖励，重复结算不重复发资源、道韵或币。详见 [奖励与经济核对](wendao-economy.md)。

## 实际验证

完整旧站 `v2.16.28/schema7` → 当前后端/schema13 → 正常关闭后二次启动，已在 SQLite 3.50.4、MySQL 8.0.39、MySQL 5.7.44、PostgreSQL 16.9 实际运行。覆盖管理开关、旧角色/洞府/作物/功法保留，旧卡牌战斗处理，秘境/大比进行中状态真实 HTTP 恢复与退出，未来 schema999 与旧二进制拒写。最新工具的额外精确断言和端口身份保护再以全新 SQLite 完整复跑；三外库为此前相同主流程，见 [整站记录](wendao-site-upgrade-2026-11-04.md)。5.7 实测版本为 5.7.44，不是精确 5.7.8。

游戏表组件三库检查、13 个固定样本的容量、失败回滚、重连二次迁移见 [容量报告](wendao-upgrade-2026-11-04.md)。样本最大共用存档 21,685 字节，不是所有合法状态的容量上界。

本轮自动检查通过：全部 `go test ./pkg/...`、问道/宗门/秘境相关 controller 回归（含新增经济契约）、模型活动事务定向测试、两套升级工具 Go 编译/检查、四项 Python 隔离测试、前端全部 **237 项 Bun 测试**、修改文件 Prettier/ESLint、最终前端生产构建及包含最终 dist 的 Go 二进制构建。构建仍有既有依赖注释和大 chunk 警告，退出成功。
