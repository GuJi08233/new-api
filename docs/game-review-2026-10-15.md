# 游戏中心逐项审查（2026-10-15）

范围为当前工作区的 28 款游戏，包括象棋行棋记录、斗地主提示与拖选等现有改动。检查了规则引擎、真实路由和请求参数、本人会话与版本校验、公开信息、结算与余额边界、关闭后的行为，以及前端 API 和交互状态。结论是对这些具体路径的审查结果，不代表没有其他缺陷。

## 本轮发现与修复

1. **奖池累计金额缺少上界检查。** 单笔和个人上限不能约束所有玩家投入的总和。隔离测试中，原模型允许奖池从 `common.MaxQuota - 2` 增加到 `common.MaxQuota`，突破钱包的记账边界，零抽成等情况下会导致派彩被拒。现在入池时在同一事务、扣币之前检查累计总额，抽券之前也验证金额和抽成范围；拒绝不会改余额、流水、奖券或截止时间，较小投入仍可继续。该复现按记账单位构造极大金额，不是默认参数下的小额快速套利路径。涉及 `model/game_jackpot.go`、`controller/game_jackpot.go`，回归在 `model/game_jackpot_test.go`。
2. **四个免费游戏的恢复入口没有检查关闭开关。** 扫雷、数独、记忆翻牌、数字华容道的 `/state` 原先仍可在单游戏或整个游戏中心关闭后读取免费对局，和同组其他操作不一致。现在统一拒绝，且不删除存档，重新开放可恢复原局。已有投入资金的下注局、玩家房间和奖池仍能在关闭后处理。回归在 `controller/game_skill_state_test.go`，同时覆盖原本已正确检查的连连看和推箱子。
3. **验证配置变化后可能残留旧状态。** 共享 Turnstile hook 原先会在免验证后保留失败状态，重新要求验证或换 site key 时可能沿用旧令牌。现在按配置和验证代次隔离状态，过期组件回调不再污染当前验证，令牌只消费一次；大转盘复用相同实现。涉及 `common/usePlayTurnstile.jsx`、`wheel/index.jsx`。
4. **扫雷多指触摸可能遗留长按计时器。** 第二根手指原先可能覆盖第一根手指的记录，松开后旧计时器仍执行插旗。现在限制主指针并按指针编号结束操作，替换前清理计时器。涉及 `minesweeper/index.jsx`。

仓库原有 GC-01（零操作挂机补奖励时长）的修复已复核：连连看零消除、AI 先手、零步认输和结尾空等不作为有效玩家时长；正常操作仍可补足此前待发奖励。未将其列为本轮新发现。

## 如何给部分游戏免除 CF 验证

进入 root 的 **游戏管理 → 基础设置 → 免开局验证的游戏**，选择游戏后保存；清空选择会恢复所有免费玩法跟随“开局验证”总开关。

- 新配置项为 `game_setting.play_turnstile_exempt_games`，值为游戏标识数组，默认 `[]`，不自动豁免任何游戏。
- 可选 17 种：11 个技巧游戏、五子棋/四子棋/黑白棋/象棋/斗地主的人机模式，以及大转盘免费旋转。
- 只有系统 Turnstile 和游戏开局验证总开关均开启、且游戏不在名单中时，才要求开局验证。全局关闭时名单仍保留。
- 玩家对战、下注与奖池原本就不要求免费开局验证；石头剪刀布不支持 AI，因此不在选项中。
- 规则由服务端按真实路由决定；客户端伪造 `game` 参数不会绕过其他游戏验证。免验证不改变登录、IP 封禁、成绩重放、奖励次数、每日奖励上限或有效游玩时长。
- 配置保存、通用选项更新和运行时重载使用相同校验与规范化；无效游戏、下注游戏和 `null` 不接受，重复项去重并排序。管理接口只提交改过的字段。

管理接口部分更新示例（仅演示，不是已应用的配置）：

```json
{
  "play_turnstile_exempt_games": ["tetris", "xiangqi", "landlord", "wheel"]
}
```

- 游戏 controller 测试、补充的 PVP/房间长轮询/有效时长测试、model 游戏账务测试通过。
- 新增回归覆盖 17 种免费玩法的 Info/Start 一致性、伪造游戏参数、付费转盘、配置写入/回读/重载，以及六种有恢复接口的技巧游戏的开关行为。

- 前端静态审查覆盖 28 个页面及共用模块；浏览器验证覆盖免验证管理、共享验证状态、大转盘验证切换、扫雷触摸边界。此前象棋及斗地主交互回归仍保留。
