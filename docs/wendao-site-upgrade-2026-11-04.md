表格四环境均实际执行了同一条完整启动/升级/恢复/拒写主流程。随后工具增加了管理开关、未用丹符精确退还和明确新版提示断言，以及端口占用拒绝、随机版本/PID身份核对、清理失败保留进程跟踪保护；**这些最终增强只在全新 SQLite 库完整复跑**，MySQL 8、MySQL 5.7、PostgreSQL 未重开执行最终脚本。另有四项确定性工具安全测试通过，不把它们当外库复跑证据。

全部使用全新唯一临时目录和全新空库，外库仅监听 `127.0.0.1`。未加载生产配置、连接生产库、安装全局软件或修改系统服务。新旧站点二进制通过临时 Go overlay 仅把监听地址改为本机，并提供停止文件向原信号通道送 SIGTERM 的测试钩子；业务路由、规则、模型、全站迁移和关闭逻辑保持原源码。每次停止均在日志确认 `received signal ... shutting down` 和 `server exited`。

MySQL 5.7.44 来自官方 `https://cdn.mysql.com/archives/mysql-5.7/mysql-5.7.44-winx64.zip`，压缩包 SHA256 为 `AED661FE8120254A1DC30F5A4D5DE346681922F4847CF025E2D4084ECA78E70E`。仅解压到本轮临时目录启动便携实例；初始化时 Windows EventLog key 无权限警告未触发提权或注册表变更，实例和实际升级均成功。这里覆盖 MySQL 5.7.44，未声称精确最低小版本 5.7.8。

每个环境均按同一流程验证：

1. 旧站完整初始化、root 登录、开启问道和大比；真实接口创建法修主角、通过序章、开宗、种植灵田、扩建静室，同时保留旧卡牌历练、大比和斗法秘境进行中状态。为开宗显式给合成测试角色金丹与材料，不将其当正常成长路径。
2. 新站同库完整启动，保留管理开关、角色、功法、节点、洞府与作物；旧卡牌战斗按 schema8 后规则结束，现有大比和秘境可通过真实接口读取并退出，随后可开始新历练斗法并带 token 退走。
3. 正常关闭、再次完整启动；GET 主角、下院、师承正常，底层保存数据与前次停止时一致。
4. 在明确可丢弃库写入 schema999 合成样本；当前站 GET 和 POST 均拒绝，原始存档字节不变。恢复本轮保存后，用真实旧二进制启动，旧版 GET/POST 拒绝 schema13，原始字节同样不变。
5. 当前站再次启动读取正常。所有检查失败即非零退出，成功报告记录引擎版本、表数量和通过项。SQLite 79 张表（含 SQLite 内部表），MySQL/PostgreSQL 78 张业务表。

本轮不是三库高并发测试，也未穷举历史版本、所有资产组合或所有活动结算；原子回滚与容量继续由 [组件验证](wendao-upgrade-2026-11-04.md) 和相关回归测试提供。旧版前端用最小占位资源以执行 API 验收；当前前端实际画面与触屏验收由主代理另行记录。
