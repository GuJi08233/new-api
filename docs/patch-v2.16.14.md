# v2.16.14 — 计费、转发和账号隔离补丁

本补丁基于 `main` 的 `e44f3195a`，将本地 `new-api` 分支中确认影响当前实现的修复适配到现有架构，保留 `web/classic/`、原始计费快照、钱包原子预扣、任务退款幂等和响应头安全透传。

## 修复内容

- HTTP 重定向以精确主机和有效端口界定凭据接收范围。跨来源清除自定义 API Key、授权头、Cookie、Referer 和 Host 覆盖；跳回原来源也不恢复凭据。禁止 HTTPS 降级和跨来源重放请求正文，保留匿名媒体跳转、SSRF 检查与跳转次数限制。Gemini 任务轮询的拒绝跳转错误也会隐藏签名 URL 中的凭据。
- 异步任务每次重试在调用上游前补足预扣，余额或令牌额度不足时不提交更贵的任务。Gemini / Vertex 实时查询与后台轮询共用终态 CAS、结算和退款流程，避免先保存失败状态后漏退，也避免重复退款。
- Claude 表达式结算将未拆分 TTL 的缓存写入余量按 5 分钟写入计费，并保留完整输入上下文长度供价格档位判断。旧倍率计费不再因普通输入输出为零而清除独立缓存费用。
- Claude 用量区分字段缺失和显式零，保留原始上游计费快照；有实际输出但缺少有效输出统计时，恢复的估算值进入结算快照。
- 流式写入按累计数据量提供时间预算，避免大型图片事件在慢网络下被固定 30 秒写超时截断。Responses 成功送达完成事件后及时结束；正常完成与真实写失败分别处理。
- Claude 请求级保活覆盖计费准备及渠道重试，并在正式响应前停止、等待退出，再交给响应流处理。启用渠道响应头透传时沿用禁止提前提交响应头的策略。
- OpenAI Chat 转 Claude 时保留连续 assistant 消息的所有工具调用；同一 chunk 内的 reasoning 和正文都发送。Gemini 支持时使用原始 JSON Schema 字段保留复杂工具及结构化输出约束；API v1 无法保留时沿用支持的子集并记录提示。
- Redis 限流脚本丢失后使用 `EVAL` 恢复，不重置已消费额度。配置了独立限流的分组按用户和分组分别计数，其余分组继续共享用户全局限制。
- 过载检测优先使用容器 cgroup CPU 配额和内存工作集；连续三次采样超阈值才拒绝请求，忽略超过 30 秒的陈旧采样，采样中断后重新累计。
- Playground 的配置和历史按账号隔离。延迟保存、异步导入、导出和重置均绑定原会话账号；跨标签页身份改变时卸载旧会话、停止旧 SSE，并提示刷新。

## 升级行为与边界

- 旧的 `playground_config` / `playground_messages` 无法确认归属，保留在原浏览器存储中，但不再自动加载或分配给新登录账号。升级后新保存的历史使用账号独立命名空间。
- 缓存计费修复会使先前漏计的 Claude 缓存用量按站点配置正常扣费；计费表达式与价格配置本身不变。
- 需要携带自定义凭据的请求不能再依赖向其他主机或端口自动转发鉴权头。请将渠道地址配置为实际接收凭据的终端；无凭据媒体链接仍可跳转。
- 旧版已经漏退、且已保存为失败终态的历史任务，需要另行核账；本补丁没有修改生产账本或自动追溯历史退款。
- 当前 main 已有的查询串日志保护和 Go 1.27.3 构建配置保持不变。没有引入上游 JS 任务插件或改变当前 Vidu 的按次价格模型。
