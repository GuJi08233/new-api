# 问道游戏表升级与容量验证记录

日期：2026-11-04。实现基于 `df38e07b955f1d7dc476ef16821c3dd340d5b4ae` 的 schema 13；演练入口和固定样本见 [工具说明](../scripts/wendao-upgrade/README.md)。本轮仅增加工具、自动检查与文档，不更改生产模型、存档版本、玩法或奖励。

## 环境与结果

本机创建全新唯一临时目录；MySQL、PostgreSQL 各使用独立实例、仅监听 `127.0.0.1`，验证库名均以 `wendao_check_` 开头。每次使用空库，未操作历史测试数据或生产库；报告不保存连接口令。运行结束后正常关闭本轮实例，保留数据和日志。

| 引擎 | 实际版本 | 新建表演练 | 旧组件表升级 | 重连后二次迁移 | `data/state` 实际类型 |
| --- | --- | --- | --- | --- | --- |
| SQLite | 3.50.4 | 通过 | 通过 | 通过 | `text/text` |
| MySQL | 8.0.39 Community Server | 通过 | 通过 | 通过 | `text/text` |
| PostgreSQL | 16.9，Windows 64-bit | 通过 | 通过 | 通过 | `text/text` |

旧组件表样本刻意省略现行的版本及计时列，插入数据后调用当前模型的 `AutoMigrate`，核对确实加列、旧字节及新增列默认值不变。该样本不冒充某次历史整站发布的完整数据库。

三库均验证：正常存档稳定往返、行版本递增、会话旧版本拒写；未来 schema 与损坏 JSON 原样保留；存档失败、会话已执行 SQL 更新后存档失败、双存档失败的事务回滚；关闭重连后全部 JSON、版本和计时字段保留。

## 容量

各引擎中相同固定样本的 UTF-8 字节数一致。主角活动互斥，每个活动使用独立存档；满派遣与满驻守分别采样。样本的完整构成、种子、时间和限制写在工具 README 与 fixture 中。

最大的本轮共用存档约 **21.18 KiB**，距离 48 KiB 工程目标仍有余量，本次没有扩容列类型。该样本原始顶层值贡献为：宗门 8,229 字节、主角 8,868 字节、收据 3,297 字节、契约簿 629 字节、秘境局外成长 278 字节、回流报告 267 字节；其他顶层值与 JSON key/标点构成余下开销。

秘境和大比单独检查真实会话外层载荷及开局状态；它们不是最深秘境或所有会话状态的容量上界。累计统计的位数和未来内容也会增大存档，因此这些结果不能证明所有合法存档都低于 MySQL TEXT 上限。
