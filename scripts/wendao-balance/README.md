# 历练斗法数值模拟

从仓库根目录运行（需要已有 Go、Bun 与项目依赖，不会连接游戏数据库或游戏接口）：

```powershell
bun scripts/wendao-balance/simulate.mjs
# 也可指定 CSV 的输出位置
bun scripts/wendao-balance/simulate.mjs C:/Temp/wendao-balance.csv
```

默认写入系统临时目录的 `wendao-balance.csv`。`main.go` 调用当前版本真实的 `Hero.JourneySetup`，导出三流派的章节首领与问心阶开局；
`simulate.mjs` 用浏览器同一份斗法规则和黄金回放的机器人运行，不复制伤害或生命公式。CSV 每行记录场景、培养、胜场、超时、
平均耗时、平均剩余生命及实际敌我加成，可检查全部 50 级，而非只看平均通关率。

固定种子为 `1, 7, 19, 41, 97, 211, 509, 1021, 4093, 8191`；机器人策略的种子为场景种子加 17，三流派的闪避概率都是 0.8，
体修倾向近战，法修、剑修倾向远程，均手动瞄向最近敌人。连续两秒没打掉敌人的生命时，额外绕行 100 帧，避免一直隔着石头射击。

三类培养均使用本流派起手斗法法宝与法术，没有宗门特产，没有丹符、随行弟子、灵兽与临时丹药：

| 样本 | 境界、层数与养成 |
| --- | --- |
| `base` 基础 | 章节对应境界一层，仅起始功法和佩戴法宝，无额外洞府、祭炼、淬体 |
| `trained` 合理培养 | 同境九层；灵泉与两件佩戴法宝（本命法宝、玄铁护心镜）的祭炼等级为章节序号（1–5）；淬体为本境上限一半；初始功法参悟六张 |
| `graduate` 本章毕业 | 同境九层；灵泉、佩戴法宝祭炼与淬体到本境上限；初始功法全部参悟；多出的佩戴栏按顺序补暖玉、玄龟甲、清心铃、聚灵玉；元婴以后服两颗九转金丹。该样本可包含本章首领通关后的养成，用于重打或终局比较 |

问心阶三类样本均用化神。模拟的每一级独立从满状态开局；不假装这是一个机器人连续打完 50 级的概率，真实角色也可在阶梯之间继续培养。
周天试炼另外覆盖五章、遭遇/强敌/首领三类、五种天象，统一用合理培养；从每章每类的第一个节点取敌人。
百鬼天象额外敌人取该地域普通敌人表第一种，本次它与各章第一个遭遇节点的第一种一致。共 729 个场景、每场 10 个种子。

旧卡牌数值直接套在斗法上时，合理培养体修的六场首领为 `10/0/4/0/0/0`，法修 `8/0/1/0/0/0`，剑修 `10/2/5/6/1/0`；
三流派毕业样本的第 50 级均为 `0/10`。本轮据此降低节点强度与阶梯的逐级增长，仍保留终局难点。

## 结果边界

- 这是确定性操作策略的数值检查，不是对真实玩家通关率、手感或培养时长的估计；机器人没有所有玩家策略，也不善于主动选择进攻窗口。
- 障碍绕行仍有局限。周天试炼有体修 56、法修 62、剑修 22 次五分钟超时，计入失败；CSV 单独列出，不能把这些全解释成伤害不足。
- 不同种子的敌人出生位置会影响瓶颈；每种场景只有十个种子，胜率的细小差异没有统计意义。
- 黄金回放另覆盖新增后三章的全部敌人，并由 Go 与浏览器双方核对逐帧校验和；这个模拟工具本身不代替重放正确性测试。
- 改动真实数值或 `JourneySetup` 后应重新运行并更新本节结果，不能继续引用这次记录。
